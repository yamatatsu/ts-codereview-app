# 00. 全体像と画面構成

## 目的

TypeScript のコードレビューで、「どこから読むか」「この変更は何に影響するか」「どのテストが守っているか」をすぐに把握できるようにします。

## 主要なユースケース

1. 自分のローカル変更（未コミットの変更、またはブランチ全体）をセルフレビューする
2. 他人の GitHub PR を、worktree に展開してレビューする
3. 変更されたシンボルの定義・参照をジャンプで辿る
4. 実装とテストを分けて読み、往来する
5. 変更ファイルの依存関係を見て、推奨順に読む
6. 読んだファイルに Viewed を付け、追加 push 後は差分だけ再レビューする

## 画面構成

```
┌──────────────────────────────────────────────────────────────────────────┐
│ [Project ▼] [ReviewTarget ▼  e.g. PR #123 / local: feature-x vs main]   │ ← ヘッダー
├──────────────┬───────────────────────────────────────────┬───────────────┤
│ Files        │  Diff / Code view                         │ Context panel │
│ ─ Review順 ─ │  (split | unified)                        │  ▸ Tests      │
│ ▾ 実装 (8)   │                                           │  ▸ Imports    │
│   ✓ a.ts     │                                           │  ▸ Imported by│
│   ・ b.ts    │                                           │  ▸ References │
│ ▾ テスト (5) │                                           │  ▸ Outline    │
│ ▸ 折りたたみ │                                           │               │
├──────────────┴───────────────────────────────────────────┴───────────────┤
│ status: LSP ready · graph 2,341 files · viewed 5/13                       │
└──────────────────────────────────────────────────────────────────────────┘
```

- 依存グラフ画面は全画面のビューとして別に開く（`Cmd+Shift+G`）
- 設定は別画面（アプリ設定とプロジェクト設定）
